# 04　判定基準にも限界がある

[前の章](03-specification-gates.md) · [目次](README.md) · [次の章](05-differential-testing.md)

判定基準（オラクル）は、特定の問いを裁定するための参照です。原版プログラム、外部エミュレータ、明示的な仕様、独立実装などが該当します。大切なのは、そのフィールドをなぜ裁定できるかです。「別の道具も同じ結果」だけでは、共通の誤った前提を持つ可能性を除けません。

## 問いに合う参照を選ぶ

| 問い | 適する参照 | 残すべき制約 |
|---|---|---|
| 原版メニューのキー応答 | 固定した原版を通常入口から再生 | 環境、初期状態、入力受付時点 |
| 復号内容は同じか | 同じ入力に対する独立デコーダ | 対応版、文字コード、エラー、コードの共通由来 |
| 命令の状態遷移は同じか | 初期状態が既知の原版／外部コア | 比較したレジスタ、メモリ、命令だけ |
| ハードウェア値の妥当な近似は何か | 公開ハードウェア契約 | 仕様近似であり、実機のサイクル一致ではない |
| 合成例の正解は何か | 人工契約と独立した手計算 | 教材内だけ。歴史的互換性を主張しない |

マニュアル、攻略、利用者の記憶も有用な問いを示しますが、説明、観察、実際のプログラム状態を分けます。「戦場の大きさ」が画面の視野と内部配列を指すことがあります。同じ言葉の層を確認してから矛盾を判断します。

## 追跡できる一回の実行

原版と候補の識別、基準の版、道具の image ID、設定、初期セーブ／状態、入力、停止条件を固定します。実行予算を設け、失敗後に背景処理を残しません。比較前に生の観測を保存し、正規化結果で上書きしません。

観測境界は「17 番目の要求の処理後」「次の命令入口」「指定フレームの描画完了後」のような識別可能な時点にします。キーを送って一秒待つだけでは、同じ状態を保証できません。時間駆動しか使えない原版なら、不確実性、反復回数、整列条件を記録し、決定性を捏造しません。

Parhelion は dispatch 境界で状態を取り、既に命令取得が進んだ分を調整しています。コアの差分検査には適しますが、ゲームを通常のメニューから目標まで進めた証拠の代わりにはなりません（P3）。

## 候補より先に再生を確かめる

同じ基準を同じ条件で二回動かし、基準同士を比較します。不一致なら、乱数、スケジューリング、設定、取得時機、非決定的フィールドを調べてから候補を判断します。二回の一致が支えるのはその条件であり、全条件の決定性ではありません。

OnePCE の記録では、Mesen2 の全速動作は描画を飛ばし、メモリが指定フレームに達しても画像が古い場合があります。そのスクリプトはフレームスキップを無効にしています（O1、O3）。模擬処理の完了と観測の更新は別々の検査です。

観測器には正の対照とエラー例を与えます。道具や必須成果物の不在は失敗にし、空ディレクトリを差分ゼロにしません。画像取得では既知の合成画像を使い、寸法、行幅、チャンネル、切り出しを確認します。

## 基準同士が矛盾したら

版と定義を合わせ、フィールドごとに証拠力を調べます。Talos の TAS 仕様は外部テストコーパスのタイミング上の限界を記し、別の参照で局所的訂正を支えつつ、他のフィールドの検査を維持しています（T4）。外部であることは無謬であることではありません。

旧期待値、修正値、理由、証拠、影響事例、未解決範囲を残します。裁定できなければ `UNKNOWN` とし、該当する適合声明を止めます。候補を最も通しやすい参照を選んではいけません。

PCM／DAC／PIT などのタイミングは、本プロジェクトの停止線に従い公開契約を優先し、`hardware-spec approximation` と記します。ハードウェア考古を再開するには別の明示的な許可が必要です。

### 出典と主張の範囲

[O1、O3、T4、P3、W2](../../inventory.md#固定來源索引)は取得、テストコーパスの訂正、状態境界、形式参照の例です。出典内容の確認は `CONFIRMED`、参照選定と再生手順は `STRONG_INFERENCE` です。エミュレータ結果を元の実機測定とは呼びません。
