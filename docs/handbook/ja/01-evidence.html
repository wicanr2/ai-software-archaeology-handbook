01　別の人が再び見つけられる証拠を残す

前の章 · 目次 · 次の章

証拠の出発点は、意味を付けた名前ではなく、位置を特定できる観測です。「ダメージ後にあるメモリ位置の値が減った」と「このフィールドは生命値だ」は別の主張です。前者には入力、位置、取得方法が必要です。後者には他の説明を除く根拠も必要です。

スクリーンショット一枚も完全な証拠ではありません。プログラムの版、初期状態、入力列、取得境界、拡大縮小や色変換の有無を記します。不足がある記録も手掛かりとして残せますが、厳密に再現可能な実験とは呼べません。

最小の証拠カード

これは手書きの作業表であり、正式なスキーマではありません。未取得の値は UNKNOWN とし、架空のハッシュで埋めません。

項目 記録する内容
証拠 ID と問い 安定した ID、何を裁定する観測か
入力の識別 原ファイル名、SHA-256、版。文書はリポジトリと完全なコミット
元の位置 パス、ページ、シンボル。アドレスには道具とアドレス空間
環境と方法 道具の版、image ID、設定、コマンド、入力列、実行予算
開始と取得条件 セーブや状態、乱数、イベント／フレーム境界、前後の状態
生の成果物 パス、ハッシュ、サイズ。画像は寸法とピクセル形式
生の観測 意味名を付ける前の実際の値
主張と確信度 解釈、支持と反対の証拠、確信度、不足箇所

文書のハッシュは読んだノートを識別するもので、そのノートが扱う EXE のハッシュではありません。Git コミットで出典を固定できますが、作業ツリーは読んでいる間にも進みます。取得と確認では同じ固定版を使います。

元の位置を保ち、意味を追加する

逆アセンブルでは元の関数名、オペランド、バイト列、アドレスを残します。自作の名前は確定事項に見えがちです。意味、確信度、出典はコメントや版管理された索引として追加し、出力時に自動で統合表示します。次の人が索引を開くことを覚えている必要がある仕組みでは、引き継ぎが不完全です。

単に health とだけ示す代わりに、次のように記録します。

元の位置 追加した解釈 確信度 証拠
原ファイル、元のオペランド、明示したアドレス空間 ある状態更新に関与する可能性 HYPOTHESIS、未確認 取得結果とアクセス箇所。不足は別記

IDA の線形アドレス、セグメント内オフセット、ファイルオフセットは交換可能ではありません。道具間の対応には各基準と対応理由が必要です。関数とデータフローの関係は解析データベースを主とし、平坦なアセンブリ文字列は検索の手掛かりとして使います。それだけで全間接アクセスを証明できません。

ゼロ件を信じる前に、検索が見えることを示す

春之石の検索は、int だけを受け入れたため、wait と表示される呼び出しを落としていました（S2）。負の検索結果を解釈する前に確認します。

  1. 正の対照：既知の存在箇所を見つけられるか。
  2. 範囲：関連領域全体か、既にコードと分類された部分だけか。
  3. 表現：シンボル、直接オペランド、基底に折り込まれたオフセット、間接アクセスを扱えるか。
  4. 分母：走査数、スキップ数、解析不能数はいくつか。

読み出しが多いのに書き込みが少なければ、アドレス取得と後続の間接書き込みを追います。直接参照一覧の欠落は書き込みの不在を証明しません。「この方法では見つからなかった」と報告し、UNKNOWN を保ちます。

観測器にも対照を与える

既知の寸法と色の合成画像で画像変換を、既知イベントでトレースを検査します。道具が開始し、完了し、必要な成果物を出したかも確認します。WinCV では変換器の不具合が後のフォント解釈を汚染しました（W1）。道具の修理だけでなく、古い出力に依存する主張の再確認も必要です。

本リポジトリの共用ホスト規則では、解析と取得を、資源制限、外側のタイムアウト、有限の寿命を持つ Docker で行います。入力は読み取り専用、書き込み先は事前に UID/GID を確認し、終了後に当該コンテナを除去します。必要な参照と独自の要約だけを残し、アクセスできることを理由に原版素材を取り込みません。

出典と主張の範囲

S2、W1、O3は検索、取得の誤り、ハッシュ記録の例を支えます。内容確認は CONFIRMED、カードと検査方法は STRONG_INFERENCE です。非破壊の注記と Docker の要件は本プロジェクトの規則です。
