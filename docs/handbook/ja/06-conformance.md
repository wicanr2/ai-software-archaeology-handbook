# 06　完了を監査できる結論にする

[前の章](05-differential-testing.md) · [目次](README.md) · [次の章](07-agent-workflows.md)

適合性とは、版を持つ契約の宣言した受入範囲を候補が満たすことです。全システムの無条件保証ではありません。CONFORMED の主語は「この候補版がこの仕様に対して」であり、版も範囲もない「プロジェクト完了」ではありません。

## 追跡可能な報告

```text
対象／候補の識別：版、コミット、バイナリのハッシュ
仕様：ID、版、受入範囲、除外範囲
基準：種類、版、入力、設定
実行：ID、初期状態、入力列、観測成果物
比較：規則版、フィールド、時点、検査分母
結果：厳密一致、許容差、不一致、欠測、スキップの件数
停止理由：完了／未実装／時間切れ／取得失敗／不一致
制約：未検査環境、不明フィールド、近似、非阻害の理由
裁定：宣言した条件を満たすか、審査者、日付
再検証条件：どの入力、道具、仕様、候補の変更で適用できなくなるか
```

これは人が書く報告の雛形であり、`osa report` が存在する証拠ではありません。実行成果物がない場合の正直な紙上報告は付録に示します。

## 要求から証拠へ逆にたどる

審査では「完了はまだ証明されていない」から始めます。元の要求を列挙して各項の証拠を探します。存在するテストからだけ要求を逆算すると、テストのない機能が消えてしまいます。

| 必須結果 | 十分な証拠 | 不十分な代用品 |
|---|---|---|
| 通常操作で完了 | 配布物、通常入口、全入力経路、出力 | テスト専用入口で結果へ直行 |
| 参照動作との一致 | 同状態の観測、比較規則、差分記録 | 単体テスト成功、似た画像 |
| 境界とエラーの意味 | 候補を判別する例、失敗後の状態 | 正常入力だけ |
| 対応環境とデータ版 | 各範囲の必要標本と入力の固定 | 別環境のビルド成功 |
| 必須観測がそろう | 実取得数が契約を満たし、成果物へたどれる | 全体の終了コードだけ |

比較不能は合格ではありませんが、製品欠陥とも限りません。証拠不足の可能性があります。両者を分けつつ、必要な証拠の不足は CONFORMED を止めます。

## 早期停止と対象外の不明点

Parhelion P1 は、306 命令が一致した後、未実装命令で停止したと記録しています。それは比較した軌跡を支えますが、p-System 全体の互換性ではありません。Talos T1 の大量の CPU テスト事例も、未完成のシステム起動の代わりにはなりません。

最初から契約が特定の命令切片だけを要求していれば、他の命令は対象外にできます。利用者が完全起動を求めたなら、未実装命令は未完了の仕事です。検査後に目標を小さくするのは、完了でなく問いの変更です。

「リメイク作業完了」「原版の厳密動作は不明」「任意の磨き込み」を分離します。不明点が妨げるかは利用者目標で決めます。難しい調査を任意作業に改称せず、非阻害の未知で納品を無期限に延ばすこともしません。

## 新版は旧版の結論を借りられない

デコーダ、観測器、許容差、入力版、パッケージの変更は報告の適用を失わせる場合があります。依存関係を説明し、相応の範囲を再検査します。旧報告は旧版の証拠として残し、新候補には新しい証拠を用意します。ファイル時刻が新しいだけでは、ビルド由来やバイナリの識別になりません。

納品では手引きの完成、ツールの完成、実事例の合格を分けます。編集検査で章、例、出典の整合性を示せても、過去の実行結果を再現済み実験として再認証はできません。

### 出典と主張の範囲

[P1、P3、T1、W1](../../inventory.md#固定來源索引)は切片の制約、停止理由、成果物識別の例です。記録は `CONFIRMED`、報告と逆向き監査の方法は `STRONG_INFERENCE` です。本書は宣言した有限範囲を検証し、標本から全域の数学的証明を主張しません。
