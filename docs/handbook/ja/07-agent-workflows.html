07　印象ではなく証拠を引き継ぐ

前の章 · 目次 · 次の章

エージェントのタスクには、検査可能な問いと今回の許可範囲が必要です。「ゲームを完成させる」は目標ですが、実行契約としては不足しています。現況、確定した判断、必須成果物、受入条件を加えます。証拠に応じて条件は具体化できますが、目標を勝手に置き換えてはいけません。

書き換えて使えるタスク依頼

目標：特定の利用者動作を調査／実装する。
版：対象、候補、有効な仕様。
既知の証拠：結論だけでなく ID を列挙。
今回の許可：DRAFT まで調査、または READY 条項を実装、など。
保持：出典データ、確定済みの製品判断、無関係のモジュール。
成果物：生の観測、主張／仕様更新、比較または阻害証拠。
受入：通常経路、必須フィールド、反例。
停止：段階ゲート、または方向を変える利用者判断の不足。

資料にある「完了」や「次にこれをする」は、現在の指示ではありません。現在のコード、有効な仕様、最近の検証を見てから必要な履歴を読みます。FD2 F1 は質問の経路案内、現況、過去の引き継ぎを分け、古い作業が勝手に再開するのを防いでいます。

一回の作業サイクル

  1. 作業ツリー、対象版、仕様、コンテナの道具を確認する。
  2. 証拠を特定し、主張と競合する説明に ID を付ける。
  3. 最小の判別観測を行い、盲点と失敗を記録する。
  4. 確信度の変更を明示し、影響する参照も更新する。
  5. READY 後に正式実装し、不足は仕様へ戻す。
  6. 局所検査、差分検査、必要な通常利用経路を実行する。
  7. 結果、範囲、不明点、次のゲートを報告し、当該コンテナを片付ける。

道具で分かる事実はエージェントが調べます。原版の欠陥を保つか、操作を変えるかといった価値判断は利用者が決めます。質問の前に、答えに依存しない調査を済ませ、具体的な選択肢と影響を示します。

許可なく公開、出典プロジェクトの変更、無関係なリファクタリングを行いません。継続の許可は範囲を自由に広げる許可ではありません。一方、手引きを完成させる許可があれば、章、例、納品を完了させます。「続けられます」という申し出だけで終わらせません。

阻害要因にも証拠が必要

よい報告には、失敗したコマンドや観測、確認した道具と権限、安全な代替の試行、必要な未回答事項、完了した独立作業があります。検索ゼロ件を資料なしとせず、環境失敗を製品欠陥と呼びません。

進捗は、何が判断を変えたか、次の観測で何が分かるかを伝えます。長い作業を見えるようにしつつ、詳細なコマンドは作業履歴に置き、大量の出力で結論を代用しません。

文書の役割と引き継ぎ

役割 内容
README 目的、安定した入口、現在の能力、閲覧／実行方法
現況文書 有効な判断、状態、制約、最近の証拠入口
作業リスト 実行可能項目、完了条件、次のゲート
WORKLOG 追記する作業履歴、失敗、検証、後片付け
研究記録／仕様 元の位置、主張、確信度、反証、受入契約

各役割には既存の唯一の文書を使い、テンプレートのために同義文書を増やしません。引き継ぎには変更ファイル、証拠、四段階の主張、検査、失敗、未解決事項、推奨する次のタスクを含めます。スキップはスキップ、原版未実行は未実行と書きます。

出典と主張の範囲

F1、P2、T2、T3は経路案内、仕様による許可、能力境界の例です。確認内容は CONFIRMED、依頼書とサイクルは STRONG_INFERENCE です。本章は手引きであり、PLAN 後半の独立したエージェント用ツールや、新しいエージェントによる実験の完了ではありません。
