# 05　同じものを比較し、最初の不一致を残す

[前の章](04-oracles.md) · [目次](README.md) · [次の章](06-conformance.md)

差分テストは同じ条件で参照と候補の観測を比較します。比較器にも契約が必要です。整列方法、許可する変換、欠測の扱い、停止規則を決めます。欠測を黙って無視すると、正しい候補と未検査の候補が同じ成功信号を返してしまいます。

## 比較前に整列する

対象版、初期状態、要求列、チェックポイント ID、取得時点、フィールドの意味を確認します。Parhelion は同じ p-code 命令の実行後に IPC、SP、TOS を比較します。一方だけ実行前なら、それは観測のずれであって規則の不具合ではありません（P3）。

出力のソートやピクセル移動をする前に、順序と位置が意味を持つか確認します。リスト順が行動順を決めるなら、ソートは検査対象の差を消してしまいます。

## 少なくとも六種類の結果を分ける

以下は報告の概念であり、公開済みの列挙型やスキーマではありません。

| 結果 | 意味 | 必須受入への影響 |
|---|---|---|
| 厳密一致 | 必要な観測がそろい、契約どおり同じ | 宣言した比較分母に含める |
| 許容差内 | 完全な観測が事前審査済みの許容差や写像を満たす | 別記し、生値の完全一致とは呼ばない |
| 不一致 | 比較可能な値が規則に反する | 該当範囲の合格を止める |
| 欠測 | 必須ファイル、フィールド、時点がない | 合格を止める。ゼロや一致ではない |
| 比較不能／不明 | 版、意味、境界が合わない | 調査または事前の除外。後から基準を下げない |
| スキップ／未対応 | 未実行、または機能がない | 合格と分離。必須項は未完了のまま |

OnePCE O2 は必要な環境変数がなければテストをスキップし、一部メモリファイルがなければその領域を飛ばします。これはコード上で確認できる危険であり、過去の受入実行が実際に欠測だったという主張ではありません。実際の検査範囲を報告する必要性を示しています。

## 最初の不一致は原因に近い

状態を持つ系では、最初にずれた時点を保存します。仕様と実行 ID、ステップ、入力、フィールド、参照値、候補値、生の成果物へのパスです。診断のため後続を取っても、累積した誤りを多数の独立した欠陥と数えません。

付録の誤った候補は `01 0A` の後、250 を 4 にします。参照は 255 で、ここですでに反例です。後で `02 00` により両方ゼロになるため、最終状態だけなら誤りを見逃します。

パーサでは複数の独立したフィールド差分を集める方がよい場合もあります。時間列では順序を保存します。すべてを同一の「最初の差分」アルゴリズムにせず、対象動作に合わせます。

## 許容差と変換は先に定義する

OnePCE O1 は表示窓と色の対応を使い、参照の外にある最終行を除外します。そのため、一フレームあたり比較 76,480 ピクセル、未比較 320 ピクセル、写像規則を残す必要があります。差分ゼロを全ネイティブ RGB の完全一致と言い換えられません。

位置探索は、どこなら最も似るかという診断に使えます。受入は仕様で予測した位置です。最良位置が二ピクセルずれるなら、期待位置を動かすのでなく幾何や取得契約に戻ります。許容規則を変更したら版を付け、旧結果を残して影響範囲を再検査します。

## 比較器と最後の出力経路を検査する

同じデータ、意図的に変えたデータ、欠けたフィールド、ずれたチェックポイントを与えます。誤った候補と不完全な観測を拒否できるか確認します。こうした故障注入は、常に成功する比較器を見つけます。検査対象自身から期待値をすべて生成しないでください。

製品では、画面、ファイル、セーブ、正式パッケージまで通す必要があります。MM2 の文字問題は、オフスクリーン比較が通っても未通過の表示転送は検査できないことを示します（M1）。通常経路、代替経路、対応プラットフォームを別々に抽出検査します。

### 出典と主張の範囲

[O1、O2、P3、M1](../../inventory.md#固定來源索引)は分母、スキップ分岐、最初の差、出力境界の例です。静的確認は `CONFIRMED`、六分類と比較器反例の方針は `STRONG_INFERENCE` です。本章のために出典プロジェクトのテストを実行したとは主張しません。
