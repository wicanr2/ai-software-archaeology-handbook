# 08　失敗の仕組みから次の観測を選ぶ

[前の章](07-agent-workflows.md) · [目次](README.md) · [一連の演習](worked-example.md)

失敗事例の目的は、次に何を調べるか示すことです。ゲーム固有の答えを暗記することではありません。八例とも[固定出典](../../inventory.md#固定來源索引)があり、因果関係の詳細は[第 0 段階の記録](../../failure-patterns.md)に保存しています。ここでは診断に使う判断へ整理します。

## 検査を通らない最後の出力：MM2 文字層（F01／M1）

内部の描画は正しく、パッケージは動き続けても、利用者には文字のない枠が見えました。出典は最終表示転送の余分な Flush を原因とし、オフスクリーン検査がそこを通らないことを記しています。テスト成功なのに利用者が誤りを見るなら、テストと正式経路の最後の違いを探します。同じ層の反復数を増やすだけでは足りません。これは統合範囲の反例であり、原版全体の互換性測定ではありません。

## 出力の形だけが合う：MM2 解凍（F02／M1、M2）

入力が尽きてもゼロを補い、宣言長まで出力したため、長さ一致が成功に見えました。出典は形式条件と合法な終端条件でその説明を否定しました。内容がもっともらしく直接の根拠がないとき、欠けた証拠をコードが補っていないか調べます。長さ、範囲、意味は別の検査です。

## 表示名が元のバイトを隠す：春之石の呼び出し検索（F03／S2）

ニーモニックのフィルタが実在する呼び出しを除き、ゼロ件を未使用と記録しました。バイトと命令開始位置を調べて盲点が分かりました。あるはずなのに見つからない場合、既知の正例を与え、表現、範囲、スキップ数を検査します。読みやすいラベルは bytes の代わりにはなりません。

## 候補を区別できない検査：春之石の生命値（F04／S3）

生命値も経験値もレベルとともに増えます。出典はダメージと死亡判定のアクセスを追い、もう一方のフィールドの不確実性を残しました。多くの標本が合うとき、競合説明も全件通るかを問います。通るなら似た標本を増やすのでなく、判別条件を変えます。

## 測定誤りが解釈を汚染する：WinCV の取得（F05／W1）

画像チャンネルのずれでテンプレートが一致せず、当初は Wine のフォント置換だと解釈されました。変換器を修理しても、旧フォント主張は別に再検証する必要がありました。道具間の不一致では既知入力で観測経路を調べ、その古い出力に依存した全主張を列挙します。

## 同フレームでも古い画像：OnePCE の取得（F06／O1、O3）

基準の状態は進んでも描画がスキップされ、画像は古い場合がありました。出典はスキップを無効にし、再生を検査しています。メモリ一致で画像不一致なら、まず画像更新の境界を確認します。実時間依存の表示と決定的な模擬進行を混同しません。

## 参照自体に欠陥がある：Talos のテストコーパス（F07／T4）

外部テストコーパスには既知のタイミング制約がありました。別の参照で局所訂正を支え、他の比較は維持しています。一つのフィールドだけ合わないなら、候補を参照の欠陥に合わせる前に、そのフィールドを裁定できる根拠を調べます。ただし期待値の変更にも独立証拠が必要です。「基準も間違うかもしれない」は反例を避ける口実ではありません。

## 静的な終点から時間列を見落とす：FD2 の導入部（F08／F2）

メニューの静的素材では、それ以前の縮小や場面転換を否定できません。出典は連続取得で解釈を修正し、開始フレームの誤認が判明して時間原点も撤回しました。素材、再生順、取得範囲を分けます。音声を観測していなければ、画像だけで音楽同期の結論を補いません。

## 再利用できる調査順序

入力と版、観測器と取得境界、比較器の範囲、仕様と候補のデータフローの順に確認します。これは調査順の推奨であり、変更のたびに全道具を再較正せよという意味ではありません。直接証拠があれば切片を狭められます。なければ不明を保ち、候補を修理できたことを旧解釈の正しさの証明にしません。

### 出典と主張の範囲

八つの記録の存在は `CONFIRMED`、教訓の再利用可能性は `STRONG_INFERENCE` です。本書のために歴史的事象を再実行していません。別の作者やソフトウェア分類で同じ効果があるかは `UNKNOWN` です。同じ作者の七プロジェクトは、独立した七チームの実験ではありません。
