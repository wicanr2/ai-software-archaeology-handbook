# 06　把完成聲明寫成可稽核的結論

[上一章](05-differential-testing.md) · [目錄](README.md) · [下一章](07-agent-workflows.md)

符合性（conformance）是候選在指定版本的契約與驗收範圍內通過比較，不是對整套軟體的無條件保證。
CONFORMED 的主詞應是「這個候選版本對這份規格」，而不是沒有版本與範圍的「專案完成」。

## 一份能回查的報告

```text
目標／候選身分：版本、提交、二進位雜湊
規格：ID、版本、驗收範圍與排除範圍
基準：種類、版本、輸入與設定
執行：ID、起始狀態、輸入序列、觀測產物
比較：規則版本、欄位、檢查點與覆蓋分母
結果：精確相符、容許差異、不相符、缺失、略過各幾項
停止原因：完成／未實作／逾時／觀測失敗／分歧
限制：未測平台、未知欄位、規格近似與非阻塞原因
裁決：是否達到宣告驗收條件；審查者及日期
重驗條件：何種輸入、工具、規格或候選變更使本報告不再適用
```

這仍是人工報告模板，不代表 `osa report` 已存在。附錄示範沒有執行產物時如何誠實地只寫教學推導。

## 由要求逐項反查證據

審查時先假設「完成尚未被證明」，從原始需求列出必要項，再逐項尋找證據。
不要只從現有測試倒推需求，否則沒寫測試的功能會自動消失。

| 必要項 | 合格證據 | 不足的替代品 |
|---|---|---|
| 正常操作能完成 | 正式產物、正常入口、完整輸入路線與輸出 | 測試專用入口直達結果 |
| 參考行為相符 | 同狀態觀測、比較規則及差分紀錄 | 單元測試通過或截圖看起來像 |
| 邊界與錯誤語意 | 可區分錯誤候選的案例、錯誤後狀態 | 只測正常輸入 |
| 支援的平台與資料版本 | 各範圍必要抽驗、固定輸入身分 | 另一平台包可編譯 |
| 無必要觀測缺失 | 實際收集數等於規格要求，且可定位 | 只有整體成功退出碼 |

無法比較的資料不是通過，也不一定是產品缺陷；它可能是證據缺口。
報告分清兩者，但只要缺的是必要證據，就不能宣布該範圍 CONFORMED。

## 提早停止與範圍外未知

Parhelion P1 記錄一致走過 306 條後停在未實作指令。這支持那段已比較軌跡，
不能改寫成完整 p-System 相容。Talos T1 的大量 CPU 語料也不能取代尚未完成的整機開機。

若規格原先就只要求固定指令切片，未實作的其他指令可以列為範圍外；
若使用者要求完整開機，那些指令便仍是未完成工作。驗收後才改小目標不是收斂，是更換題目。

「重製已完成」「原版精確行為仍未知」「可選潤飾」應分開列。未知是否阻塞，
依使用者目標判定，不能因研究很難就改叫潤飾，也不能因存在非阻塞未知而無限拖延交付。

## 新版本不能借用舊版本的結論

修改解碼器、擷取器、容差、輸入版本或正式封包，都可能使報告失效。
只需重驗受影響的合理範圍，但必須能說明相依關係。保留舊報告，它仍證明舊版本發生過什麼；
新候選要有自己的證據。檔案時間較新不能取代建置來源或二進位身分。

發布時把手冊完成、工具完成與真實案例通過分開說。本書的編輯檢查可以證明章節、例子與來源一致，
不能把來源歷史結果重新認證成已重跑的原版實驗。
