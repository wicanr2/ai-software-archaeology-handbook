跨專案模式矩陣

本表只比較來源索引中的固定提交。 「反覆出現」指不同專案留下相同類型的可核對實踐或失敗紀錄，不代表統計上的普遍性。 七個專案來自同一作者，可能共用規範與工具，不能當成七個獨立團隊實驗。

有來源支持的重複模式

每列的來源觀察為 CONFIRMED（本輪讀檔／讀碼）；右欄方法主張為 STRONG_INFERENCE，仍需後續案例挑戰。

ID／模式 跨專案觀察 可重用規則與適用限制
R1 保存原始觀測與修正歷史 MM2 M1／M3 保存舊路線及新測結果；春之石 S2／S3 保留錯誤過濾與錯誤判定；WinCV W1 記錄工具修復前後的解釋 結論可撤回，原始定位與反證理由要留下；正文仍需指向現況，不能只追加歷史而放任舊規格繼續被引用
R2 信心依讀寫端與判別證據提升 春之石 S3 分開已定位的生命值與仍缺結算端的經驗值；MM2 M1 保留鏡射強推論被新樣本否定的過程；Parhelion P2 分開證據、推論及自訂 合理名稱、單調數據或少量樣本不夠；每個主張獨立分級，不能一批升格
R3 先約定可實作範圍與閘門 Parhelion P2 明定 DRAFT／READY／CONFORMED；Talos T2 是 READY、T3 仍是 DRAFT、T4 有排除範圍 閘門應逐子系統判定；已完成控制協定不表示已完成整機或收據格式
R4 同一觀測邊界與可重播輸入 MM2 M3 用新鮮副本重測選單至神殿；OnePCE O1／O3 固定畫格且關閉跳幀；Parhelion P3 在 dispatch 邊界擷取與逐步比較 時間、輸入、起始狀態與擷取邊界都是實驗條件；相同按鍵字串不自動代表同一執行
R5 比較層次與覆蓋分母分開 MM2 M1 內部畫布測試漏掉最終顯示；OnePCE O1／O2 區分記憶體、像素及未覆蓋列；Talos T1 區分 CPU 語料與完整遊戲 單元正確、決定性、行為一致、使用者路徑各自報告；未觀測欄位不可計為相符
R6 觀測工具與外部基準也會錯 WinCV W1 的截圖位元組寬度錯誤；OnePCE O1 的跳幀污染；Talos T4 的語料時序限制；春之石 S2 的搜尋漏計 比較失敗時先分類觀測鏈與候選實作；基準修正須有獨立理由，不能為了讓結果變綠調整預期
R7 保留可定位的機器觀測及停止原因 OnePCE O3 記錄輸入、工具及輸出雜湊；Parhelion P3 保存步數、欄位、期望值、實際值及停止原因；Talos T2 明定未實作錯誤 機器輸出不能只有布林成功；需知道比了什麼、何處分歧、是否提前停止。這是資料需求，不是本輪正式 schema

建議項目的覆蓋核對

PLAN 建議面向 對應模式／證據 未證實部分
證據保存、來源追溯 R1、R7；O3、T4 有雜湊 未核對所有歷史附件仍可重生
信心等級、原始資料與語意分開 R2；S3、P2 各專案並未全部採相同四級詞彙
決定性重播、行為基準 R4、R6 本輪未實測重播的一致性
截圖／畫格與狀態比較 R5；O1、P3 像素一致不能取代未比較的狀態
規格閘門 R3 未全面稽核來源專案是否每次都遵守
分層測試 R5 歷史通過數不是本輪測試數
失敗文件 R1、R6 僅抽樣有明確反證鏈的案例
代理指令 F1 問題路由、P2 閘門、T2 控制契約 尚未做全新代理的獨立可用性試驗

差異與不能直接一般化的做法

分歧 來源 對本手冊的影響
原版程式、成熟模擬器、格式參考實作都可作基準，但裁決範圍不同 M3、O1、W2、T4、P3 每次先宣告基準能裁決什麼；不能統一稱為「原版真值」
正常玩家路徑與狀態擷取適合不同問題 M1／M3 對比 P3 指令核心可從已知狀態比較；產品可玩性仍須正常入口
像素比對可含裁切與色彩對應規則 O1 對比 W1 的格點與字模量測 容差／正規化先聲明；不能把經色彩映射的結果描述成所有原生 RGB 完全一致
停止研究與完整平台支援是不同交付目標 T1、P1、各 remake 現況 明列已驗範圍；有限切片可以交付，但名稱要反映限制
歷史文件職責並不一致 P2 把勘誤集中 PLAN；S1／W1 放 CONTEXT；F1 另外路由歷史與現況 本專案沿用目前狀態表與唯一 WORKLOG，不照抄檔名配置
素材與授權處置不同 W2 與本專案 AGENTS §8 本專案不匯入原版安裝檔、字庫、截圖或資料包；私人儲存庫也不豁免既有禁止事項

尚待驗證的提案

  • HYPOTHESIS：統一的證據關聯與缺失觀測欄位可減少代理把「略過」誤報成「通過」。 可由後續合成範例與新代理試驗檢驗；現在不選定序列化格式。
  • HYPOTHESIS：自動提示結論的下游引用，比只在勘誤表追加更能防止舊假說繼續流通。 M1／M2、W1 提供動機，尚沒有本專案的效果測量。
  • UNKNOWN：上述方法對其他作者、非遊戲軟體及更大規模團隊的效益。
