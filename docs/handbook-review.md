# 手冊交付驗收

## 範圍與授權

本輪目標為專案負責人的「完成手冊」，涵蓋 PLAN 第 1 階段九章與先前指定的繁體中文、
英文、日文版本。第 0 階段已先交付七個案例、七個有來源模式及八個失敗案例。
本輪重新審讀這些材料並依後續授權完成手冊，沒有冒稱使用者已逐條核驗原始證據。

中文原稿先完成並審讀，演練數值確認後才撰寫翻譯。英文與日文是完整對應版本，
不只是摘要。交付為可直接閱讀的 Markdown；未要求或宣稱完成網站、PDF、CLI、
正式 schema 或真實 oracle 介接器。PLAN 第 2–7 階段不以本文件宣布完成。

## 編輯審查的關鍵裁決

- `CONFIRMED`：在手冊中，來源紀錄存在與原版行為被本輪重現是兩個不同主張；各章均保留此區別。
- `CONFIRMED`：三種語言的人工範例均有 A01、B01–B08 九個檢查點、每點 value 與結果碼，共十八項欄位比較。
- `STRONG_INFERENCE`：章節的工作表、反例與自我檢核足以支持初學者跟著操作；本輪沒有招募外部讀者，因此不宣稱已完成真人可用性研究。
- `HYPOTHESIS`：這套方法能在更多作者及軟體類型中降低錯誤；仍需後續獨立案例驗證。
- `UNKNOWN`：七個來源專案全部歷史附件的目前可重生性，以及未重跑的原版行為；不阻塞有明確來源限制的手冊交付。

特別檢查了合成案例不虛構 run、OnePCE 缺檔風險不被寫成已發生事故、Parhelion 的 306 條不被寫成全系統相容，
以及 Talos 的局部勘誤不被擴張成硬體考古授權。翻譯保留同樣限制。

## 可重跑的文件檢查

執行 [tools/check_handbook.py](../tools/check_handbook.py) 檢查三語檔名、來源 ID、信心詞、
本機連結與錨點、表格、圍欄、明顯佔位字樣，以及完整演練的數值和三語一致性。
腳本只讀文件，不實作 `osa`，也不把結構檢查冒稱原版相容性或完整翻譯品質證明。

從專案根目錄執行：

```sh
timeout 30s docker run --rm --network none --memory 256m --cpus 1 --pids-limit 64 \
  -u "$(id -u):$(id -g)" -v "$PWD:/work:ro" -w /work \
  python:3.12-slim python tools/check_handbook.py
```

本輪 Python image ID：`sha256:229a2c5bfa27522db7815ea81f9bed70af17ccb9de9fc7ad142b1877b5830d36`。
Markdown 另以 Pandoc 3.10 的 GFM 解析與 HTML 轉換檢查；image ID：
`sha256:8d7467e8ee40b0365a344c3d41067d6d2349da52e9961e4229f331094806fb14`。
這不等於真人閱讀或跨瀏覽器視覺驗收。執行結果與交付提交記在 [WORKLOG.md](../WORKLOG.md)。
